# エルメスジャポン新商品LINE通知ツール　セットアップ手順

パソコンに何もインストールしません。すべて無料のクラウドサービス（GitHub）の上で動かします。
やることは大きく分けて3つです。

1. LINEに通知を送るための「窓口」を作る（LINE Developers）
2. プログラムを置く場所を作る（GitHub）
3. 15分ごとに自動実行するように設定する（GitHub Actions）

所要時間の目安：30〜40分（LINEアカウントとGoogleアカウント相当のメールアドレスがあればOK）

---

## ステップ1：LINE通知用の「公式アカウント」を作る

これは「エルメスの新商品情報をあなただけに送る、あなた専用のLINE公式アカウント」を作る作業です。

1. ブラウザで https://developers.line.biz/console/ を開き、お使いのLINEアカウントでログインします。
2. 「プロバイダー」を作成します（名前は何でもOK、例：「個人用」）。
3. 作成したプロバイダーの中で「チャネルを作成」→「Messaging API」を選びます。
4. チャネル名（例：「エルメス通知」）、チャネル説明、業種などを適当に入力して作成します。
   - 業種は「個人」を選べる項目があればそれを選んでください。
5. 作成できたら、そのチャネルの管理画面を開きます。
6. 「Messaging API設定」タブを開き、下の方にある **「チャネルアクセストークン（長期）」** の「発行」ボタンを押します。
   - 発行された長い英数字の文字列をコピーして、メモ帯などに一時保存してください（後で使います）。
7. 同じ画面に **QRコード** が表示されています。これはあなたの通知用LINE公式アカウントのQRコードです。
   - **ご自身のLINEアプリでこのQRコードを読み取り、「友だち追加」してください。** これをしないと通知が届きません。
8. 「応答メッセージ」「あいさつメッセージ」の設定は、LINE Official Account Managerで両方オフにしておくと画面がすっきりします（必須ではありません）。

これでLINE側の準備は完了です。控えた「チャネルアクセストークン」は後で使います。

---

## ステップ2：GitHubにプログラムを置く

1. https://github.com/ にアクセスし、無料アカウントを作成します（お持ちでなければ）。
2. ログイン後、右上の「+」→「New repository」をクリック。
3. リポジトリ名を決めます（例：`hermes-notifier`）。
4. **「Private」を選択**（他人に見られないようにするため）。
5. 「Create repository」をクリック。
6. 作成された空のリポジトリ画面で、「uploading an existing file」というリンクをクリックします。
7. お渡しした以下のファイル・フォルダをすべてドラッグ＆ドロップでアップロードします。
   - `index.js`
   - `categories.json`
   - `package.json`
   - `state.json`
   - `.github`フォルダ（中に`workflows/check.yml`が入っています）
   - `README.md`（このファイル）
   - フォルダごとドラッグすれば、GitHubが自動的に中の構造を保ってアップロードしてくれます。
8. 一番下の「Commit changes」ボタンを押してアップロードを確定します。

---

## ステップ3：チャネルアクセストークンをGitHubに登録する

プログラムの中にトークンを直接書かず、安全な場所（Secrets）に保管します。

1. リポジトリ画面上部の「Settings」タブを開く。
2. 左メニューの「Secrets and variables」→「Actions」をクリック。
3. 「New repository secret」ボタンを押す。
4. Name欄に **`LINE_CHANNEL_ACCESS_TOKEN`**（大文字・アンダースコアも含め、この通りに）と入力。
5. Secret欄に、ステップ1でコピーした長いトークン文字列を貼り付ける。
6. 「Add secret」で保存。

---

## ステップ4：動作テスト（手動実行）

1. リポジトリ画面上部の「Actions」タブを開く。
2. 初回は「I understand my workflows, go ahead and enable them」のようなボタンが出れば押して有効化します。
3. 左側に「エルメス新商品チェック」というワークフローが表示されるのでクリック。
4. 右側の「Run workflow」ボタン→もう一度「Run workflow」で手動実行します。
5. 数十秒〜1分ほどで実行が終わります。緑のチェックマークが付けば成功です。
   - 最初の1回は「今ある商品を記録するだけ」で、LINE通知は届きません（既存商品を全部「新商品」と誤通知しないための仕様です）。これは正常です。
6. 実行結果をクリックし、「新商品をチェックしてLINEに通知」のログを開くと、「商品数: 30件 / 新規: (初回のため通知なし)」のような表示が確認できます。

これで自動化は完成です。以降は15分おきに自動実行され、新商品が見つかるとLINEに届きます。

## 監視するカテゴリを増やしたいとき

`categories.json` というファイルをGitHub上で直接編集できます。

1. リポジトリ画面で`categories.json`を開く。
2. 鉛筆マーク（Edit this file）をクリック。
3. 以下のような形式で追加します（カンマの位置に注意）。

```json
{
  "name": "スカーフ",
  "url": "https://www.hermes.com/jp/ja/category/women/scarves-shawls-and-stoles/silk-scarves-and-accessories/"
}
```

4. 保存（Commit changes）。次回の自動実行から反映されます。
5. 新しく追加したカテゴリは、その次の実行が「初回」扱いになるので、最初の1回だけ通知が来ません。

## 通知頻度・間隔について

現在は15分おきに設定しています（`.github/workflows/check.yml`内の`cron: '*/15 * * * *'`の部分）。

GitHub Actionsは仕様上5分より短い間隔には設定できません。また、実際に無料枠（プライベートリポジトリは月2000分）に収まるかどうかは、実際の1回あたりの実行時間を見てから判断するのがおすすめです。

**実行時間の確認方法**
1. 「Actions」タブを開き、実行済みのワークフローをクリック
2. 画面右側あたりに実行時間（例：「37s」「1m 12s」など）が表示されます
3. その秒数 ×（1日の実行回数）で、1日あたりの消費時間の目安が分かります（15分おきなら1日96回）

もし無料枠に余裕がありそうなら、`cron: '*/15 * * * *'`の部分を`cron: '*/5 * * * *'`（5分おき）などに書き換えて、また「Commit changes」で保存すれば反映されます。

## 30件を超えるカテゴリについて

商品が31件以上あるカテゴリでは、プログラムが本物のブラウザ（Puppeteer）を裏側で動かし、「もっと見る」ボタンが無くなるまで自動でクリックしてから商品情報を読み取る方式にしています。こたろ先生に何か作業をしていただく必要はありません。

ステップ4の手動実行後、ログの中に以下のような警告が出ていないか一応確認してください。

```
[警告] https://www.hermes.com/... : サイト側の総数は65件ですが、48件しか取得できませんでした（「もっと見る」ボタンをクリックしきれなかった可能性があります）。
```

出ていなければ正しく全件取得できています。出ていた場合はご連絡ください、クリック回数の上限などを調整します。

**注意**：ブラウザを裏側で動かす分、以前より1回の実行に少し時間がかかります（数十秒〜1分程度）。GitHubの無料枠（プライベートリポジトリは月2000分）を使うので、30分おきの実行でも通常は枠内に収まりますが、心配な場合はリポジトリの「Settings」→「Billing」→「Actions」で使用状況を確認できます。

## うまく動かないときは

- Actionsタブの実行結果（赤い×マーク）をクリックすると、エラーの詳細ログが見られます。
- 「商品データ(hermes-state)が見つかりませんでした」というエラーが出た場合、エルメス側がサイトの構造を変更した可能性があります。その際はまたご相談ください。
- LINEに通知が来ない場合、ステップ1-7の「QRコードで友だち追加」をしたかご確認ください。これを忘れると通知は送信されていても届きません。
